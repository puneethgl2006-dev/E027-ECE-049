# Decision Log — Team E027 (`ECE-049`: Manufacturing Yield and Rework Tracker)

**Team Members:** Puneeth Kumar G L (`1AT24UE053`) & Purvitha B V (`1AT24UE054`) — Section ECM B

1. **DL-01 (Language Selection):** Chose Python 3.10+ with standard library modules (`csv`, `dataclasses`, `decimal`, `pathlib`) so the CLI engine runs deterministically on any evaluation machine without external package installation failure risks.
2. **DL-02 (Exact Monetary & Percentage Precision):** Used `decimal.Decimal` with `ROUND_HALF_UP` (`0.1` for percentages, `0.01` for Rs currency) instead of `float` to eliminate binary floating-point rounding drift in `yield_report.csv` and `defect_pareto.csv`.
3. **DL-03 (Pre-Expanded Serial Range Index):** Expanded each work order's `serial_from`..`serial_to` range into an in-memory `serial_to_wo` hash map during `LOAD_WORK_ORDERS` to achieve $O(1)$ `UNKNOWN_SERIAL` lookup per event.
4. **DL-04 (Validation Precedence Order):** Enforced event check precedence in strict order—(1) silent duplicate filter, (2) `UNKNOWN_SERIAL`, (3) `WO_CLOSED`, (4) `BOARD_SCRAPPED`, and (5) `SEQUENCE_ERROR`—so terminal work-order and board states take priority over stage comparisons.
5. **DL-05 (Silent Duplicate Composite Key):** Defined duplicate events via the composite tuple `(serial_no, stage, timestamp)` stored in `seen_events` (`BR-08`), silently dropping repeats like `EV-01004` (line 1005) before any state or error logging.
6. **DL-06 (Pointer-Based Stage Progression):** Tracked each board's required next stage using an integer index `expected_stage_idx` (`0 -> AOI`, `1 -> ICT`, `2 -> FCT`) that only increments on a `PASS`, automatically enforcing same-stage re-entry after a `REWORK` failure (`BR-01`, `BR-02`).
7. **DL-07 (Logged Board State Naming):** Initialized boards internally as `IN_PROCESS` prior to their first event while emitting `IN_TEST`, `REWORK`, `SCRAP`, or `SHIPPED` in `board_log.csv` (`new_state`) to match the evaluation schema.
8. **DL-08 (Rework Count Cap on 3rd Failure):** Incremented `rework_count` only when a board is actually sent to `REWORK` (`rework_count < 2`); on the 3rd non-fatal failure (`SN-00308`), transitioned `new_state` to `SCRAP` while keeping `rework_count = 2` since no 3rd rework is performed (`BR-02`).
9. **DL-09 (Fatal Defect Zero-Rework Rule):** Checked `defect_code.startswith("X")` before the rework counter so fatal defects (`X01`, `X02`, `X03`) immediately transition the board to `SCRAP` without adding Rs 150 rework labor (`BR-03`).
10. **DL-10 (First-Pass Yield Flagging):** Added a dedicated boolean `had_any_failure` on `BoardState` alongside `rework_count == 0` so only `SHIPPED` boards with zero failures across all three stages count toward `first_pass_boards` (`BR-04`).
11. **DL-11 (Scrap Cost vs. Rework Cost Separation):** Partitioned rework labor (`Rs 150.00 * rework_count`) mutually exclusively: rework labor on `SCRAP` boards is folded into `scrap_cost` alongside `material_cost_rs`, whereas rework labor on non-scrapped (`SHIPPED` or `in_process`) boards is reported in `rework_cost` (`BR-06`).
12. **DL-12 (Immediate Work-Order Closure Trigger):** Evaluated work-order closure (`BR-07`) immediately after every terminal transition (`SHIPPED` or `SCRAP`) so any subsequent event for that work order (such as `EV-00151` at line 152 on `WO-0001`) is rejected with `WO_CLOSED`.
13. **DL-13 (Physical CSV Line Number Tracking):** Used `enumerate(reader, start=2)` when loading `test_events.csv` (counting the header row as line 1) so `errors.csv` outputs exact physical line numbers (`152`, `368`, `456`, `1166`).
14. **DL-14 (Pareto Tie-Breaking Determinism):** Sorted accepted failure counts using the tuple key `(-count, defect_code)` so equal-frequency defects (`D01` and `D05` at 10 occurrences each) deterministically rank in ascending alphabetical order (`BR-08`).
15. **DL-15 (Dual-Runner Test Suite Compatibility):** Structured `test_tracker.py` using `unittest.TestCase` methods so the exact same file runs via `pytest test_tracker.py -v` or standard library `python -m unittest test_tracker.py -v`.
